# Sharvin Hariharan

Student developer interested in AI, software systems, and hardware.

I spend most of my time building things that help me understand how technology actually works rather than just learning technologies individually. Most of my projects start with a problem or an idea, and then turn into research, prototyping, debugging and rebuilding.

## What I work on

My main interests are around:

* Artificial Intelligence and Machine Learning
* Large Language Models and AI agents
* Behavioural modelling and prediction
* Full-stack web development
* Embedded systems and IoT
* Hardware-software integration
* Automation and intelligent systems

I work primarily with Python, JavaScript, TypeScript, HTML/CSS and MicroPython, along with whatever technologies a particular project requires.

## Current interests

A lot of my recent work has been around AI systems that do more than just generate text.

I'm particularly interested in how models can be used for prediction, reasoning, decision making and automation, and how they can be combined with conventional software rather than treating an LLM as the entire product.

I've also been exploring embedded systems, especially systems where sensors provide real-world data and software has to interpret that data and respond to it.

## Some things I've built

I've worked on projects involving:

* AI-based behavioural prediction
* AI agents and automated workflows
* Sensor-based embedded systems
* ESP32 and MicroPython
* Real-time monitoring and control systems
* Web applications and interactive interfaces
* Hardware and software working together as one system

A few of these projects started as fairly simple experiments and became much larger once I started understanding the problem properly. I actually prefer that process because it usually leads to learning things that wouldn't come up while following a normal tutorial.

## How I learn

I learn best by building.

If I don't understand something, I would rather build a small system around it, break it, figure out why it broke and rebuild it than just memorize how it is supposed to work.

That has led me into a pretty wide range of areas. I don't consider myself specialised in one particular technology yet, but I have a strong interest in understanding systems from the lower-level implementation all the way up to the final product.
